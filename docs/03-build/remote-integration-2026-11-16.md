# 원격 변경 통합 검토 — 2026-11-16

대상은 `origin/main`의 `c08b76d`까지 추가된 33개 커밋이다. `feat/launch-readiness-20261116`에 병합하며 운영 배포와 main 직접 변경은 수행하지 않는다.

## 통합 결정

- 최신 학생 랜딩, 수업 중심 검색 `/student/search`, 강사 작업 공간, 승인 신청, 포트폴리오, 매칭과 언어 프로필을 유지했다. 기존 강사 검색은 `/student/teachers`로 옮겨 수업 검색에서 연결했다.
- 원격의 인증 시간 제한·승인 진입·역할 안내를 유지하며 Google 신규 계정 역할 확정, 준비 상태 검사, 이메일 인증과 비밀번호 복구를 연결했다. 기존 계정의 역할은 변경하지 않는다.
- Next 15.5.29와 sharp 0.35.5를 유지한다. 원격의 Next 14 전용 라우터 패치와 검증은 15 이상에서 건너뛴다. 새 동적 화면은 Next 15 경로 API에 맞췄다.
- 원격 `0035` 이후에 출시 SQL `0036`~`0047`을 배치했다. 요청형 수업의 개별 시간·수업 길이, 고정 회차, 휴무·정원·승인 검사를 함께 유지했다. 운영자 일정 변경도 상품별 시간표를 검증하며 고정형 상품에 임의 회차를 만들지 않는다.
- `0048`에서 강사 회의 링크 RPC를 비공개 저장소에 연결했다. 기존 공개 세션 컬럼에 링크를 쓰는 것은 차단하며 강사 화면은 `/sessions/[id]`의 수업방·자료 관리로 연결했다.
- 공개 카탈로그·추천·언어 조회에도 비승인·데모·제한 강사 제외 규칙을 적용했다. 원격 신규 개인 자료 테이블에도 계정 활동 제한 검사를 연결했다.
- 원격 UI가 호출하지만 SQL에 없던 `delete_teacher_lesson`을 추가했다. 예약 이력이 있는 상품은 삭제하지 못하며 게시 해제로 보존해야 한다.
- 전체 통합 스키마에서 DB 타입을 다시 생성했다. Supabase 클라이언트의 생성 타입 연결을 유지한다.

## 검증과 한계

`npm test`는 기존 출시 기능과 원격 회귀 검증을 함께 실행한다. 원격 SQL 8개는 로컬 PostgreSQL(PGlite)에서 카탈로그, 매칭, 공개 언어, 강사 작업 공간, 개인 도구 RLS, 포트폴리오 RLS, 승인 신청·복구를 검증한다. 별도 통합 테스트는 요청형 수업 길이, 고정형 임의 회차 거절, 공개 노출 제한, 회의 링크 비공개 저장과 소유권, 예약 상품 이력 보존을 확인한다.

통합 결과는 자동 테스트 89개, 타입 검사, 경고 없는 lint, 프로덕션 빌드를 통과했다. Chrome에서 공개·계정·수업 화면 fixture(390/1440px), 수업 검색·필터·상세·예약 진입(320~1440px), 학생·강사 로그인·회원가입·이전 경로 이동을 확인했다. 실제 외부 결제·메일 발송·운영 DB 변경은 검증 범위에 포함하지 않는다. 실제 서비스 환경의 OAuth·Storage·cron·웹훅은 스테이징에서 별도 확인해야 한다.

수업 검색 브라우저 검증 중 프로덕션에서 React hydration 오류 #418이 간헐적으로 관찰됐다. 개발 모드와 마지막 프로덕션 재실행은 통과했지만 원인을 확정하거나 수정 완료로 판정하지 않았다. 테스트는 오류를 무시하지 않으며 발생 URL을 출력하도록 보완했다. 스테이징의 첫 진입·새로고침·연속 이동에서 재현 여부를 추가 확인해야 한다.

## 배포 전 남은 확인

1. 원격 기존 SQL에는 `0017` 버전 파일이 두 개 있다. 로컬 SQL 실행은 두 파일을 모두 검증하지만 Supabase 배포 도구의 버전 이력과는 별개다. 운영 적용 이력과 스키마를 대조해 이력을 정리한 뒤 신규 SQL을 배포해야 한다. 기존 적용 파일을 임의로 재번호화하지 않았다.
2. 출시 브랜치의 이전 SQL 번호는 미배포를 전제로 옮겼다. 혹시 별도 환경에서 이전 사본을 적용했다면 먼저 그 환경의 이력을 대조해야 한다.
3. Git 토큰의 workflow 권한이 없어 CI는 비활성 템플릿이다. `docs/operations/github-actions-ci.yml.example`을 권한 있는 계정에서 활성화해야 자동 검증이 실행된다.
4. 최종 사업자·정책·외부 계정 설정, 정산 수수료 확정, 정산 후 환불 원장 조정, 실제 탈퇴 삭제, 백업 복원 검증은 기존 출시 보고서의 미완료 항목으로 남는다.
